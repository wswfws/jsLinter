# **JS-Linter**
JS-линтер - это инструмент, помогающий анализировать написанный на JavaScript код, выводя найденные синтаксические ошибки. Есть файл с описанием стиля кода, а линтер проверяет код на соответствие стилю.

## **Описание стиля**
### **Описание стиля кода содержит:**
- правила для расстановки пробелов
- правила для пустых строк
- правила по неймингу идентификаторов

## Как использовать?
1. **Установите все зависимости с помощью**

`pip install requirements.txt`

2. **Запустите программу**

- Если надо запустить линтер для всех существующих директорий в папке:

`python ./main.py --directories ./`

- Если надо запустить линтер для конкретных файлов, можно их перечислить таким образом:

`python ./main.py --files .\\test2.js .\\test1.js`

### После запуска программы вы получаете в консоли все найденные ошибки в указанных JS файлах.

## Структура
**Основные методы находятся в модуле checkers:**
1. **correct_naming.py** -- файл с функциями, проверяющими названия функций, переменных и классов
2. **empty_lines.py** -- файл с функциями, проверяющими на допустимое количество пустых строк
3. **missing_semicolons.py** -- файл с функциями, проверяющими пропуск точек с запятой
4. **spaces_style.py** -- файл с функциями, проверяющими на корректный стиль отступов между символами (по типу присваивания и прочее)

**В модуле self_types:**
1. **js_code.py** -- содержит классы для работы с анализом кода JavaScript

**Также существуют следующие файлы:**
1. **main.py** -- файл для запуска линтера
2. **public_props.py** -- файл с утилитой для извлечения списка публичных свойств объекта, исключая приватные и защищённые
3. **config.py** -- файл с конфигурацией для запуска основного скрипта
4. **test1.js и test2.js** -- тестовые js-файлы
5. **config.yml** -- файл с описанием стиля js-кода
6. **requirements.txt**

**folder tests:**
   1. test_correct_naming.py
   2. test_empty_lines.py
   3. test_missing_semicolons.py
   4. test_spaces_style.py

### Подробнее про файл config.yml:
Файл содержит описание стиля, по которому и будут проверяться файлы с js-кодом.

**Что в нем прописано?**
- **max-code-line-without-empty-lines** -- число, описывающее максимальное количество строк кода без пустых строк
- **missing-semicolons** -- булево значение, если True - разрешено пропускать ;, если False, соответственно нельзя.
- **spaces-style**:
- - **before** -- значит, что перед этими символами должен быть пробел
- - **no-before** -- перед этими символами нет пробела
- - **after** -- после этих символов должен быть пробел
- - **no-after** -- после этих символов нет пробела
- **naming-patterns** -- устанавливаются регулярные выражения для переменных, констант, функций и классов.
